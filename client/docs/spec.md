# Spec：登录页「同意用户使用协议」竖条改横排

## 1. 现象与根因（已代码级确认）
- 现象：login 场景中 `user-agreement` 节点渲染成一条竖条——勾选框在顶部、竖排文字「同意用户使用协议」，节点尺寸 `56 × 335`。
- 素材：该节点 `cc.Sprite` 使用图集 `hall_ui` 的帧 `按钮-user-agreement.png`，帧本体即 `56(宽) × 335(高)` 的**竖版**图（rawWidth 56 / rawHeight 337）。把这张图逆时针转 90° 后，文字正读、勾选框在左 —— 说明它是「横排横幅被转 90° 导出」的素材。
- 直接证据（布局对齐）：同层兄弟节点 `tick`（勾选标记，50×44）位于 `(-140, -220)`。若横幅按横排摆放（335×56，中心 `(0,-220)`），其左边缘 x=-167.5，内绘勾选框中心≈ -137.5 —— 与 `tick` 的 (-140,-220) 几乎重合。**说明原始设计是横排，当前竖排是错误状态**（`tick` 现在悬空在竖条左侧）。
- 直接原因：节点 `_eulerAngles.z = 0`（无旋转），故素材按竖版原样显示。

## 2. 目标
`user-agreement` 恢复为横排：勾选框在左、文字「同意用户使用协议」横向可读，并与 `tick` 重叠对齐；位置保持 `(0, -220)`。

## 3. 变更（唯一文件）
文件：[login.fire](file:///d:/babykylin_scmj/client/assets/module/login/login.fire)
节点：`__id__12`（`"_name": "user-agreement"`，父节点 `__id__9` = `main`）

| 字段 | 现值 | 改为 |
| --- | --- | --- |
| `_trs.array[3..6]`（qx,qy,qz,qw，当前 L663-678） | `0, 0, 0, 1` | `0, 0, 0.7071067811865476, 0.7071067811865476` |
| `_eulerAngles.z`（当前 L684） | `0` | `90` |

旋转方向依据（仓库内既有样例校准）：[mjgame_ldh.fire](file:///d:/babykylin_scmj/client/assets/module/mjgame/mjgame_ldh.fire#L38341-L38358) 中既有节点 `_eulerAngles.z = -90`，其 `_trs` 四元数为 `qz = -0.7071067811865475, qw = +0.7071067811865476` —— **qz 与 eulerZ 同号**，即正角度 = 逆时针。本例需要把素材逆时针转 90° 才回正，故取 `+90`。

保持不变：`_contentSize` 56×335、锚点 (0.5,0.5)、位置 (0,-220)、Sprite 组件与所引帧、`tick` 节点及其位置。

## 4. 验证步骤
1. Cocos Creator 编辑器打开 `login` 场景，选中 `user-agreement`：应显示为横向横幅（覆盖区约 335×56），文字正读、勾选框在左，并与 `tick` 重合；不再与下方 y=-279 的「抵制不良游戏…」`tips` 行重叠。
2. 预览运行 login 场景：登录页底部呈现一行 `[☐ 同意用户使用协议]`。

## 5. 回滚
将上表 2 处数值还原（`_trs.array[3..6] = 0,0,0,1`、`_eulerAngles.z = 0`）即可，无其他连带改动。

## 6. 已知风险 / 兜底
若编辑器渲染为文字倒置、勾选框在右（即旋转方向相反），改为 `_eulerAngles.z = -90` 且 `_trs.array[5] = -0.7071067811865476`（其余不变）。依仓库样例推断应为 `+90`，此项仅为兜底。
